# Figures

Deliverable: the figures the round's storyline asks for, rendered, referenced,
and verified in the built PDF.

Read the injected accepted-input context: the `paper-storyline` result, whose `context`
block carries the manuscript paths, the figures directory, the reference spec
path and the venue, and whose `figure_directives` array names what must change
this round.

Upstream results are not workspace files: each entry in the `inputs.json`'s
`inputs[]` carries the producer's worker name, `resultPayload`, and the
`resultPath` it was written to. Read them from there.

**`figure_directives` is the round's figure work list.** There is no other
channel: the reviewer's figure findings reach this stage only as entries in that
array, transcribed by `paper-storyline`. If it is empty, use the reference
spec's `figure_grammar` to judge whether the existing figures already do their
job, and fix what does not — an empty array is permission to leave the set
alone, not an instruction to.

## 1. Plan before drawing

For each figure the target unit needs, write down before writing code:

- **role** — the job it does (headline-speedup, scaling, ablation, breakdown,
  design diagram, workload spread). The role picks the grammar entry.
- **message** — the one sentence the reader should be able to repeat after
  looking at it. If you cannot state it in one sentence, it is two figures.
- **data source** — the exact file(s) it plots. The brief's `evidence` lists what
  exists; verify the path resolves and inspect the file's real columns before
  plotting. A figure script written against a guessed schema produces a figure
  of the wrong thing.
- **comparison** — what is compared against what, and which horizontal line marks
  parity.

If a needed datum is missing, do not invent it and do not substitute a similar
one. Put the figure in `not_rendered` with the reason; `paper-audit` and
`paper-review` must be able to see that the paper is missing evidence it claims.

## 2. Generate from data

- **Plot with a script, committed.** Extend the manuscript's existing figure
  pipeline when one exists (the brief's `figures_dir` and reference papers show
  the convention). A figure whose script is not in the repository cannot be
  regenerated by the artifact evaluator, and the loop will eventually need to
  move a number.
- **Vector only.** PDF/SVG for plots; TikZ/PGF for diagrams. No screenshots, no
  embedded PNG of a terminal.
- **Typography.** Match the paper's font family and size so the figure does not
  read as an insert. Set the size in the script to the final print size —
  scaling a figure in LaTeX rescales its fonts too.
- **Print-legible.** Line widths and marker sizes must survive at column width;
  use a colourblind-safe palette and distinguishable markers, never colour
  alone, because the reference papers' figures also read in greyscale.
- **Annotate the grammar's marks.** Baseline band, sample counts, winner's
  numeric speedup, error bars — whatever the reference figures for this role
  always show.

## 3. Caption

Structure per the reference spec:

1. First sentence: **the claim** the figure establishes.
2. Following sentences: **how to read it** — axes, what is compared, what the
   annotations mean.
3. Never repeat the surrounding prose. Never leave the reader to infer units.

Quote-and-adapt: take the caption shape from the role's `caption_exemplar`, and
put the paper's own numbers into it.

## 4. Verify, in this order

1. **Script runs clean** from the working directory. Re-run it and confirm the
   output's mtime changed.
2. **Output is vector** and its size is sane for a column or page width.
3. **LaTeX compiles** with the figure included. Add the `figure` environment with
   `\label{}` and reference it from the sentence that discusses it. Run the
   compile command from the brief's `manuscript.compile`.
4. **The page is clean** — no overfull box from the figure, no figure pushed away
   from its first reference, caption not orphaned from the image.
5. **Read it at print size.** Open the built PDF at 100% and answer: could a
   reviewer get the message without the caption? If not, the figure is decoration.

Record for each figure: `rendered`, `verified_in_latex`, the script path, the
output path, and the caption you used. Where verification failed, say which of
the five steps failed.

## 5. Self-check

- [ ] Every figure has one stated message.
- [ ] Every plotted value comes from a file, and the file path is recorded.
- [ ] The generation script is in the repository and re-runs clean.
- [ ] Output is vector and printed at its final size.
- [ ] Caption's first sentence is a claim, not a title.
- [ ] The manuscript compiles with every figure you reported as rendered.
- [ ] Missing evidence is in `not_rendered`, not approximated.
